How Army Passion fits together

One system that replaces the Excel sheets: it finds the grants each soldier's family can get, fills the forms, tracks the applications and keeps the colonel in touch with the families. This page explains the parts and how information moves between them.

Upload a sheet

frontend app/upload/page.tsx, ColumnMapping, ImportPreview · API /api/imports/*
  1. Choose the file — drag it in or press a button.
  2. Check the columns — each heading is matched to a field (rules first, then the LLM, only headings are sent). Extra columns: he picks Add or Leave out. Missing fields are listed and stay empty.
  3. Check and save — a preview of every change; he can fix values, skip rows, add or remove columns. Only then is anything written, with the old value kept in history.

Add a family

frontend app/families/new/page.tsx · API POST /api/families · services/family_create.py
  1. Only two boxes are needed: the soldier's name and the next of kin's name.
  2. Typed values go through the same cleaners as an Excel row (dates, +91 phones, PIN, IFSC). A mistake is explained under the box.
  3. If it looks like a family we already have, he is shown the match and decides.
  4. A missing phone does not block saving; it goes on the "missing details" list.

CEA claims — who can claim

frontend app/cea/page.tsx · API GET /api/cea/eligibility · services/cea.py
  1. Every family is checked against the CEA rules for the chosen year (default: last year, because claims go in after the year ends).
  2. The rules are data in app/data/cea_scheme.json: two eldest children, KG–12, up to age 20, monthly rates.
  3. Families are sorted into four tabs. Each verdict comes with reasons in plain words.

CEA claim form

frontend app/cea/[familyId]/page.tsx · API /api/cea/families/{id}/form, POST /api/cea/pdf · services/cea_form.py
  1. Every box is pre-filled from the database; empty ones are listed at the top as he types.
  2. Save writes only the boxes he changed back to the family's record, old value kept in history. A blank never wipes anything.
  3. Download PDF writes the values onto the official scanned form: cover letter, contingent bill, self-declaration, and one school certificate per child.

The data

The main tables in PostgreSQL. One soldier ↔ one family; a family has many members, documents, applications and calls.

families core

  • widow / NOK, phones, language
  • address + map point (PostGIS)
  • pension & bank, record office
  • extra_fields — new columns from his sheets

soldiers · postings

  • name, rank, army no, unit
  • date, cause, place, weather of death
  • postings — also the colonel's, for talking points

family_members

  • widow, children, parents
  • date of birth → turning 18, CEA ages
  • school, class, hostel → CEA

schemes · eligibility

  • rules as JSON — CEA is the first real one
  • verdict per family, with reasons
  • "becomes eligible on" date

applications · stage events

  • form filled → signed → submitted → received → credited
  • stuck after N days
  • KSB DAK ID

documents · interactions · voice

  • files per family or child
  • calls and voice notes, transcripts

field_history · audit_log

  • every change: old, new, source, who, when
  • who did what in the system

data_quality_issues

  • missing phone, bad date, duplicate…
  • feeds "families with missing details"

import_batches · custom_fields

  • each upload and its confirmed columns
  • remembered layouts, approved extra fields

The principles

The rules every part of the system follows.

Never overwrite

Every change keeps the old value, the new value, where it came from (Excel, call, voice note, officer), when, and who.

AI suggests, a human decides

Column matching, voice notes and eligibility are suggestions. Nothing is saved until an officer confirms.

Rules are data

Eligibility rules and rates live in the database, not in code. They are deterministic and tested.

Swappable services

WhatsApp, speech, LLM, eSign and storage sit behind interfaces with a mock version, switched by settings in .env.

Simple for everyone

Large text, plain words, one clear action per screen, works on a phone. Families use WhatsApp, not an app.

Indian formats

DD-MM-YYYY dates, +91 phones, ₹ with Indian grouping, Asia/Kolkata time.
